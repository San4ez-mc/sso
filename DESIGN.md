# SSO FINEKO — єдиний вхід для всіх продуктів

> Один акаунт людини на всю екосистему (трекер, орг.структура, контент). SSO відповідає
> лише на «ХТО це» (автентифікація). «ЩО можна» (доступи) — обчислює орг.структура.
> Пов'язано: #281 (рішення про ідентичність, напрям Б), `SYSTEM_MAP.md` у репо org.

## Навіщо
- Людина логіниться раз — має доступ у всі продукти, без окремих паролів.
- Одна база людей на всю інфраструктуру (фундамент для «захопити компанію повністю»).
- Продукти довіряють SSO: він видає підписаний токен, вони його перевіряють.

## Способи входу (провайдери) — розширювана модель
1. **Email + пароль** (базовий; скид пароля через SMTP — спільний примітив надсилання).
2. **Google** (OAuth 2.0 / OpenID Connect) — найпопулярніший.
3. **Microsoft** (Azure AD / Outlook) — для бізнес-клієнтів.
4. **Apple** (Sign in with Apple) — часто вимога для мобільних.
5. **Facebook** (за потреби, B2C).
6. **Telegram Login** (widget або через бота — як уже роблено у трекері: бот шле
   тимчасове посилання входу).
Кожен провайдер — окремий модуль `providers/<name>`; додати новий = новий модуль.

## Модель даних (чернетка)
- `User { id, primaryEmail, displayName, status(active/disabled), createdAt }`
- `Identity { userId, provider, providerUserId, email, linkedAt }` — кілька провайдерів
  на одного User (вхід і через Google, і через пошту — той самий акаунт).
- `Session/Token { userId, issuedAt, expiresAt }` → підписаний JWT.
- **Доступи тут НЕ зберігаються** — їх дає орг.структура за userId (посади/ролі).

## Потік
1. Продукт → редірект на SSO `/authorize?client_id&redirect_uri` (як OAuth).
2. SSO показує вибір провайдера → логін → створює/знаходить `User` (мердж за email).
3. SSO → редірект назад із кодом → продукт міняє код на токен (`/token`).
4. Продукт перевіряє токен (`/introspect` або підпис) → знає userId.
5. Для доступів продукт питає орг.структуру: ролі/посади цього userId у компанії.

> Патерн і код можна взяти з наявного OAuth-сервера трекера (`OAuthController`) —
> там уже є authorize/token/introspect + Telegram-вхід + скид пароля.

## Адмінка (для власника)
- Список людей: email, підключені провайдери, компанії/ролі (з орг.структури), статус.
- Дії: деактивувати/поновити, злити дублікати акаунтів, відв'язати провайдера,
  надіслати запрошення/скид пароля, подивитись останні входи.
- Пошук/фільтр по email/компанії/статусу.

## Зв'язок із доступами (важливо)
- SSO = ідентичність. **Орг.структура = джерело правди доступів.**
- Зміна посади/видалення в орг.структурі → права перераховуються всюди самі
  (продукти щоразу питають актуальну роль, не кешують назавжди).
